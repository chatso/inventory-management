System architecture

Three layers, one direction of dependency. The browser holds all UI state; the server is stateless apart from data loaded once at startup.

Tech stack

Deliberately small: no state-management library, no ORM, no chart library.

Frontend

  • Vue 3 (^3.4) with setup() Composition API
  • Vue Router 4, history mode, 6 routes
  • Axios (^1.6) for HTTP
  • Vite 8 + @vitejs/plugin-vue 6
  • Node ^20.19 or >=22.12
  • Hand-built SVG charts, scoped CSS, slate palette
  • Two locales (en, ja) with currency switching

Backend

  • Python FastAPI with auto-generated /docs
  • Pydantic models for response validation
  • Uvicorn ASGI server on port 8001
  • uv for environment and dependency management
  • Plain Python list comprehensions for filtering
  • JSON files as the only data source

Quality and tooling

  • pytest + FastAPI TestClient
  • scripts/start.sh and stop.sh launch both servers
  • .claude/ agents, skills, slash commands, hook
  • MCP config for Playwright and GitHub
  • No frontend tests, linter, or CI config in the repo

Data flow

How a filter change in the UI becomes a re-rendered chart. Filtering is server-side; derived display values are client-side.

  1. User changes a filter FilterBar writes to four module-level refs in useFilters: period, location, category, status. Because the refs live outside the function, every component shares the same state.
  2. The active view reacts A watch() on those refs (for example in Dashboard.vue) fires and calls getCurrentFilters(), which maps location to warehouse and period to month.
  3. api.js builds the request Filters equal to 'all' are omitted from the query string. Axios sends GET http://localhost:8001/api/.... The base URL is hard-coded.
  4. FastAPI filters in memory The route calls apply_filters() (warehouse, category, status) and filter_by_month(), which accepts 2025-03 or a quarter such as Q1-2025. Inventory endpoints ignore month because inventory has no date.
  5. Pydantic validates the response The result is serialised as JSON through the route's response_model. CORS middleware permits the cross-origin call from port 3000.
  6. The view derives and renders Raw responses go into refs; computed() properties turn them into KPIs, status breakdowns, category totals and trend series, which the template renders as custom SVG and CSS Grid.

Observations

Gaps found while reading the code. None stop the app from running.

Task and purchase-order endpoints are missing from the backend api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET), but main.py defines no such routes. App.vue catches the errors and shows only the mock tasks from useAuth. PurchaseOrder models and an empty purchase_orders.json exist, but nothing writes to them.
Backlog.vue is not routed The view exists but main.js registers no /backlog route, so it is unreachable from the UI. The dashboard shows backlog data through its own computed property.
Demo-grade configuration Data resets on every server restart. The API base URL is hard-coded to localhost:8001, CORS allows every origin, and authentication is a mock user with no real login.
Duplicated quarter logic QUARTER_MAP drives order filtering, while /api/reports/quarterly re-implements the same month-to-quarter mapping as an if-chain.
